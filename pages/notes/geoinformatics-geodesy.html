Geodesy, GNSS and geoinformatics work by Aditya Kumar Jha

A guide to my project work in GNSS CORS processing, high precision levelling, Python GIS automation, remote sensing and GeoAI.

By Aditya Kumar Jha · Updated 14 October 2026

From observations to usable spatial information

I am a GIS engineer based in Dehradun, India, with a B.Tech in GeoInformatics from NSUT Delhi. My portfolio describes work at Survey of India's Geodetic & Research Branch and an earlier research internship at DGRE, DRDO. I also build geospatial products through Uday GeoAnalytics Consultancy. This page connects those areas to the project descriptions and technical notes where the methods, tools and reported outcomes are explained.

My main focus is the overlap between geodesy and software: preparing observations, checking data quality, running processing workflows and making the results easier for a team to use. GNSS CORS processing with GAMIT/GLOBK and PRIDE PPP-AR

My GNSS work covers automated acquisition and preprocessing of RINEX observations, followed by processing in GAMIT/GLOBK and PRIDE PPP-AR. The case study describes multi-day and annual datasets, static and kinematic processing, and quality checks for cycle slips, completeness and satellite geometry.

The central engineering problem is repeatability across a CORS network. A useful pipeline needs the same preparation steps and quality checks to run consistently, while preserving the information needed to investigate station-specific issues. My portfolio reports a reduction from seven to three days of processing per station and twelve hours of manual work saved each week in the described workflow. These are project-specific results, rather than a performance promise for every dataset.

Read the GNSS CORS processing case study for the problem, data, method, system and results. Related tools are listed on my skills page.

High precision levelling, network adjustment and vertical datums

My high precision levelling work includes height datum computation, loop closure analysis, systematic error correction, geopotential numbers and Helmert orthometric heights. The published HPL case study describes processing and validation of 1,00,780 ground control points and adjustment software for more than 1,00,000 observations together.

The technical note explains the software implementation and the quality-control approach, including the Tau test and global statistical validation. A count of ground control points and a count of observations describe different things; they should be kept separate when discussing this work. The reported computation improvement belongs to that implementation and its comparison, rather than a universal benchmark for levelling software.

Explore the HPL network processing project and read the levelling adjustment software technical note.

Python GIS and geodesy automation

I use Python to connect data acquisition, preprocessing, computation and quality checks. Examples in this portfolio include GNSS batch processing, levelling calculations, LiDAR filtering and geospatial product workflows. My listed tools include NumPy, Pandas, GeoPandas, GDAL/OGR, PostgreSQL/PostGIS and FastAPI.

For a new automation project, the useful starting point is an example input and a clearly defined output: file formats, coordinate reference system, processing steps, acceptance criteria and expected data volume. This makes it possible to discuss what should be automated, which checks must stay visible and how the workflow will be handed over. Public code and project documentation can be explored through my GitHub profile.

Remote sensing, LiDAR, hyperspectral analysis and flood risk mapping

At DGRE, DRDO, my portfolio describes preprocessing and analysis of a LiDAR point cloud of approximately three million points and hyperspectral data with 32 bands. Python tooling included laspy and Spectral Python. The project pages separate the point-cloud and hyperspectral work from the flood-risk mapping workflow.

The flood mapping case study describes a QGIS scenario based on elevation, terrain and drainage layers, including a one-metre sea-level-rise scenario. It is presented as a spatial analysis project. A scenario map and an operational flood forecast serve different purposes; the underlying project page provides the context for interpreting the output.

Read the LiDAR and hyperspectral case study, explore the flood-risk mapping project, or view the Kosi flood map project.

GeoAI and land use / land cover classification

The UGD LULC Engine is my portfolio's land use / land cover classification project. Its description covers a PyTorch pipeline trained on EuroSAT, a QGIS-integrated labelling workflow and a reported validation accuracy of 98.1%. That number refers to the stated validation setting; it does not establish the same accuracy for every region, satellite image or operational deployment.

Planned products described on the project page include GreenWatch, VillageLens, CarbonSight and ReportGen. Other geospatial product examples include rooftop solar assessment, village flood alerts and groundwater-related analysis. Their individual pages explain the intended use and project status.

Read the UGD LULC Engine case study or browse all geospatial projects.
