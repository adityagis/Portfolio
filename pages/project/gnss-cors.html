01

Overview

I wrote Python pipelines that download and preprocess GNSS data automatically, which saves 12 hours of manual work every week. The multi-day datasets are then processed in GAMIT/GLOBK and PRIDE PPP-AR to centimeter-level accuracy across 1023+ reference stations.

The NSRF Wing at Survey of India handles GNSS CORS data for 1023+ reference stations. With the automation in place, processing takes 3 days per station instead of 7, and 365-day datasets run in batches.

Station coordinates are derived in both static and kinematic modes. Before processing, every observation file is checked for cycle slips, data completeness and satellite geometry. I also worked with a team of 5 geodetic engineers to standardise data collection across all 1023+ stations, and I document the processing methods so the wider team can run them.

03

Process

Problem → Data → Method → System → Result

  1. 01 Problem

    GNSS data from 1023+ CORS reference stations was being processed by hand.

  2. 02 Data

    Multi-day GNSS datasets (RINEX), including 365-day datasets, from CORS reference stations.

  3. 03 Method

    GAMIT/GLOBK and PRIDE PPP-AR processing in static and kinematic modes for centimeter-level accuracy. Quality control covers cycle slip detection, data completeness checks and satellite geometry assessment.

  4. 04 System

    Python pipelines for automated GNSS data acquisition, preprocessing and batch processing.

  5. 05 Result

    3 days per station instead of 7, and 12 hours of manual work saved each week.

04

Results

  • Centimeter-level accuracy across 1023+ reference stations.
  • Processing time reduced from 7 days to 3 days per station.
  • 12 hours of manual processing saved every week.
  • One set of data collection protocols across 1023+ stations, agreed with a team of 5 geodetic engineers.
